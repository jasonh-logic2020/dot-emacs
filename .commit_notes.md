### Decision: X Events Only for Emacs Testing

**Date:** 2026-03-22

**Decision:** All Emacs testing must be done exclusively via X keyboard/mouse events
(using xdotool). emacsclient --eval is prohibited for testing.

**Rationale:**
- emacsclient --eval caused Emacs to hang unresponsive after `find-file-noselect`
  evaluations, blocking the server socket for subsequent connections.
- The find-file-noselect approach ran outside the normal event loop and left Emacs
  in an inconsistent state (open connections, modal prompts).
- X events simulate real user interaction, exercising Emacs exactly as a user would.
- xdotool extracted to /tmp/xdotool-extract/usr/bin/xdotool (not system-installed;
  use dnf install xdotool when root access is available).

**How to apply:**
- Use `DISPLAY=:0 xdotool key --window <WID> <key>` to send keys.
- Main Emacs window WID: 77594772 (verify with `xdotool search --name "emacs"`).
- Use C-x C-f to open files, check mode-line after file loads.
- Capture state by having Emacs write to files (via keyboard macros or M-:).

### Fix: treesit-auto tsx/fundamental-mode root cause

**Root cause:** `global-treesit-auto-mode` only adds advice on `set-auto-mode-0` to remap
modes that already have an existing mode in `auto-mode-alist`. Files like `.tsx` have NO
legacy mode (typescript-tsx-mode is not installed), so they fall through to fundamental-mode.

**Fix applied to init.el:** Added `(treesit-auto-add-to-auto-mode-alist 'all)` BEFORE
`(global-treesit-auto-mode +1)` in the treesit-auto use-package `:config` block. This
directly registers all ts-mode file extensions in `auto-mode-alist`.

### Fix: EGLOT C stack overflow on missing LSP servers

**Root cause:** `(prog-mode . eglot-ensure)` caused EGLOT to attempt starting for every
programming buffer. With `eglot-booster-mode` active, each attempt ran
`emacs-lsp-booster <server-cmd>`. When `<server-cmd>` (e.g. `bash-language-server`,
`cmake-language-server`) is not installed, `emacs-lsp-booster` exits with code 1, and
the resulting process-sentinel cascade triggered `Re-entering top level after C stack overflow`.

**Fix applied to init.el:** Replaced `(prog-mode . eglot-ensure)` hook with
`(prog-mode . apm-eglot-ensure-if-server-available)`. The new function calls
`eglot--lookup-mode` to find the configured server program for the current major mode,
then checks `executable-find` to confirm it is actually installed before calling
`eglot-ensure`. If no server is found or the executable is missing, EGLOT is not started.

### Fix: Obsolete package deprecation warnings (cl.el, linum.el)

**Date:** 2026-03-22

**Root cause (linum):** `nlinum` package directly `(require 'linum)` in its source,
loading /obsolete/linum.elc and triggering "Package linum is deprecated" in *Messages*.

**Fix:** Replaced `nlinum` use-package with `display-line-numbers` (Emacs 26+ built-in).
`display-line-numbers-mode` supersedes both `linum` and `nlinum` with better performance.

**Root cause (cl):** `sr-speedbar` directly `(require 'cl)` in its bytecode, loading
/obsolete/cl.elc. The macros from cl were already expanded at compile time; only cl-lib
runtime support is needed.

**Fix:** Added `:preface (require 'cl-lib) (unless (featurep 'cl) (provide 'cl))` to
sr-speedbar use-package. This pre-provides 'cl so sr-speedbar's (require 'cl) finds it
already loaded and skips /obsolete/cl.elc.

### Fix: pdf-info-check-epdfinfo error at startup

**Date:** 2026-03-22

**Root cause:** `org-pdftools.el` does `(require 'pdf-tools)` at load time. This triggers
`(require 'pdf-annot)` which has a `custom-declare-variable` for `pdf-annot-list-listed-types`
whose default value initialiser calls `pdf-info-markup-annotations-p()` → `pdf-info-features()`
→ `pdf-info-process-assert-running()` → `pdf-info-check-epdfinfo()`. The epdfinfo binary
is not compiled (missing `poppler-glib-devel`), so `pdf-info-check-epdfinfo` errors.

**Fix:** Pre-set `(put 'pdf-annot-list-listed-types 'saved-value '((text file squiggly
highlight underline strike-out)))` in the org-pdftools `:init` block. When
`custom-initialize-reset` sees a non-nil `saved-value`, it uses that value directly instead
of calling the server-querying initialiser.

### Fix: Communication with Emacs via xdotool

**Date:** 2026-03-22

**Correct xdotool pattern:**
- Use `xdotool windowactivate --sync OUTER_WID 2>/dev/null; sleep 0.5` to ensure focus
- Use `xdotool key --clearmodifiers KEY` WITHOUT `--window` flag (sends to active window)
- The `--window WID` flag fails with BadMatch on GTK inner windows

- Do NOT use `eval-expr` (M-:) for evaluation: paredit-mode overrides RET preventing execution

# Commit Notes — 2026-03-23

## Session: Stack Overflow Diagnosis and Startup Cleanup

### Fix: flycheck-overlay deep recursion (Lisp nesting > max-lisp-eval-depth)

**Root cause:** `flycheck-overlay--enable` calls `flycheck-overlay--maybe-display-errors`
synchronously when `flycheck-overlay-mode` is activated via `flycheck-mode-hook`.
During `global-flycheck-mode` activation in `after-init-hook`, `flycheck-mode` fires
for every prog-mode buffer, each call adding to the already-deep startup call stack.
With `max-lisp-eval-depth 10000`, the combined depth exceeded 10000 frames.

**Fix applied:** Replaced `:hook (flycheck-mode . #'flycheck-overlay-mode)` with an
`add-hook` in `:init` that wraps activation in `run-with-idle-timer 0.1`. The idle
timer runs at event-loop top level (shallow stack), avoiding the overflow.

### Fix: flymake-proc-legacy-flymake "Can't find a suitable init function"

**Root cause:** `(add-hook 'find-file-hook 'flymake-find-file-hook)` in the flymake
use-package adds the legacy `flymake-proc-legacy-flymake` backend to every visited
buffer. When the desktop restored `/tmp/emacs-warnings.txt` in `text-mode`, and
`flyspell-mode` called `sit-for(0)` triggering redisplay/post-command-hook, flymake
started and `flymake-proc-legacy-flymake` errored because text-mode has no init fn.

**Fix:** Removed `(add-hook 'find-file-hook 'flymake-find-file-hook)` from the flymake
use-package. Language-specific backends (flymake-grammarly, flymake-shellcheck,
flymake-kondor) activate via their own per-mode hooks.

### Fix: Desktop restoring /tmp ephemeral files

**Root cause:** `desktop-files-not-to-save` default only excludes TRAMP remote paths.
Files like `/tmp/emacs-warnings.txt` (debugging temp files) were saved and restored,
triggering errors in the minor modes being activated for those buffers.

**Fix:** Added `(setq desktop-files-not-to-save "\\(^/tmp/\\|^/dev/\\|^/proc/\\)")`.

### Fix: report-time-since-load printing "nil"

**Root cause:** `(report-time-since-load)` called with no args; `%s` in the format
string formats Elisp `nil` as the string "nil".

**Fix:** Changed to `(or suffix "")` in the format call.

### Diagnostic approach used: stack inspection for circular call patterns

To identify the flycheck-overlay recursion, init.el was temporarily modified to:
- Lower `max-lisp-eval-depth` to 400 (short backtrace, readable circular pattern)
- Wrap `debugger` to auto-write backtrace to `/tmp/emacs-overflow-backtrace.txt`
- Start Emacs with `--debug-init`

The absence of the backtrace file confirmed no overflow at depth 400; the *Backtrace*
buffer showed the flymake error instead, which was the only remaining issue.
